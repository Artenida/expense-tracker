# Sprint 02 · Enums that carry behaviour

**Time:** ~1 hour · **Prerequisites:** 01 · **Produces:** `Category`, `BudgetStatus`

---

## Purpose

Most people first meet `enum` as a list of names — a nicer set of constants. That is
the least interesting thing it does. A Java enum is a class: it can have fields, a
constructor, methods, and static factories. Putting the *rules* about a value next to
the value itself is the difference between

```java
if (status == BudgetStatus.EXCEEDED) { bar.getStyleClass().add("status-exceeded"); }
else if (status == BudgetStatus.WARNING) { bar.getStyleClass().add("status-warning"); }
else ...
```

and

```java
bar.getStyleClass().add(status.cssClass());
```

The second one cannot drift out of sync when you add a fifth status. This sprint is
where the project's two most-read types get written, and they are read constantly
because everything downstream mentions them.

Neither class needs `BigDecimal`, a database, or a window. Both are pure logic with
zero dependencies — the easiest possible place to start.

## New concepts

### 1. An enum constant is an object

```java
public enum Category {
    GROCERIES("Groceries", 40_000),
    TRANSPORT("Transport", 12_000);

    private final String displayName;
    private final long suggestedLimitCents;

    Category(String displayName, long suggestedLimitCents) { ... }
}
```

Read that as: `GROCERIES` is a pre-built instance of `Category`, constructed once when
the class loads, with `displayName = "Groceries"`. There are exactly seven `Category`
objects in the running program and no way to make an eighth.

Three consequences worth knowing:

- The constructor is **implicitly private**. You cannot write `new Category(...)`.
- `==` is safe and idiomatic for comparing enums, unlike almost every other type in
  Java. Because there is exactly one instance per constant, identity and equality are
  the same thing.
- `values()` returns all of them, `valueOf(String)` looks one up by name, and
  `name()` gives the name back. These are generated by the compiler — you will not find
  them in your source.

### 2. `_` in numeric literals

`40_000` is the same as `40000`. Java lets you put underscores anywhere inside a
numeric literal for readability. You will see this used for cents throughout the
project, because `1_234_56` reads as "1,234.56" at a glance and `123456` does not.

### 3. A static factory that decides which constant applies

`BudgetStatus.of(spent, limit)` takes two numbers and returns one of four constants.
This is the pattern that keeps a *rule* in one place. The alternative — every caller
writing its own `if` chain against the thresholds — is how two parts of an application
end up disagreeing about what "over budget" means.

The rule itself has a trap in it, and it is the reason this is worth its own sprint.

## The threshold trap

The specification says WARNING begins at exactly 80%. The obvious implementation is:

```java
BigDecimal percent = spent.divide(limit, 2, RoundingMode.HALF_UP).movePointRight(2);
if (percent.compareTo(new BigDecimal("80")) >= 0) return WARNING;   // WRONG
```

Spend 79.996% of a budget. `HALF_UP` rounds that to `80.00`, and a budget that is *not*
at the threshold reports WARNING. The test the spec asks for — "79.99% is OK" — passes,
because 79.99% happens to round down. The bug hides behind a green test.

**Decide on the integers, never on the rounded percentage:**

```java
// spent >= 80% of limit   ⟺   spent * 100 >= limit * 80
if (spentCents * 100 >= limitCents * 80) return WARNING;
```

Both sides are exact `long` arithmetic. Nothing rounds, so nothing can round wrong.
The percentage still gets computed — but only for *display*, in sprint 05, where being
half a cent off does not change a decision.

This is a general habit worth taking from here: **round for humans, never for
branches.**

## Reading check

1. Why is `==` safe for comparing two `Category` values when it is wrong for two
   `String`s?
2. `BudgetStatus.of` checks `EXCEEDED` before `WARNING`. What goes wrong if you swap
   the two checks?
3. Someone edits the database by hand and sets a category to `FOOD`. Where does the
   program notice, and what does the user see?
4. Why does `suggestedLimitCents` return a `long` rather than a `BigDecimal`, given
   that PLAN.md insists money is `BigDecimal` in Java?
