### Fields — all `private final`

| Field | Type | Notes |
|---|---|---|

| `amount` | `BigDecimal` | Always scale 2 |
| `category` | `Category` | |
| `description` | `String` | Stored trimmed, 1–100 chars |
| `date` | `LocalDate` | The day the money was spent |
| `createdAt` | `Instant` | When the row was first written |

### The private constructor

Does all validation, then assigns. Collect messages from all three validators before
throwing, so a dialog can show every problem at once rather than one per attempt:

```java
private Expense(String id, BigDecimal amount, Category category,
                String description, LocalDate date, Instant createdAt) {
    List<String> errors = new ArrayList<>();
    errors.addAll(Validation.amount(amount == null ? null : amount.toPlainString()));
    errors.addAll(Validation.description(description));
    errors.addAll(Validation.date(date));
    if (category == null) errors.add("category is required");
    if (!errors.isEmpty()) throw new ValidationException(errors);

    this.id          = Objects.requireNonNull(id);
    this.amount      = amount.setScale(2, RoundingMode.UNNECESSARY);
    this.category    = category;
    this.description = description.trim();
    this.date        = date;
    this.createdAt   = Objects.requireNonNull(createdAt);
}
```

`RoundingMode.UNNECESSARY` means "normalise the scale to 2, and throw if that would
require actually rounding". Since `Validation.amount` already rejected three decimals,
reaching the throw means a bug — which is what you want it to say.

### Factories

```java
public static Expense create(BigDecimal amount, Category category,
                             String description, LocalDate date) {
    return new Expense(UUID.randomUUID().toString(), amount, category,
                       description, date, Instant.now());
}

public static Expense restore(String id, BigDecimal amount, Category category,
                              String description, LocalDate date, Instant createdAt) {
    return new Expense(id, amount, category, description, date, createdAt);
}
```

`restore` runs the same validation. That is deliberate: if a row in the database is
invalid — because someone edited the file by hand — you want to find out at the mapper
in sprint 07, not three layers later when a total comes out wrong.

### `edit`

```java
public Expense edit(BigDecimal amount, Category category,
                    String description, LocalDate date) {
    return new Expense(this.id, amount, category, description, date, this.createdAt);
}
```

Keeps identity (`id`) and history (`createdAt`); replaces everything the user can
change. Re-validates, because it goes through the same constructor.

### Accessors

`id()`, `amount()`, `category()`, `description()`, `date()`, `createdAt()`.

No `get` prefix — the modern convention, and the one records use, so the codebase stays
consistent when sprint 05 introduces records.

### `equals` / `hashCode`

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Expense other)) return false;
    return id.equals(other.id)
        && amount.compareTo(other.amount) == 0        // compareTo, not equals
        && category == other.category                  // == is fine for enums
        && description.equals(other.description)
        && date.equals(other.date)
        && createdAt.equals(other.createdAt);
}

@Override
public int hashCode() {
    return Objects.hash(id, Money.toCents(amount),    // normalised — see README §3
                        category, description, date, createdAt);
}
```

`o instanceof Expense other` is a **pattern match for instanceof** (Java 16+). It tests
the type and declares the variable in one step, so there is no separate cast line.

### `toString`

Include the id and the amount. You will read this in test failure messages for the next
sixteen sprints, so make it useful:

```java
return "Expense[" + id + " " + Money.format(amount) + " " + category + " on " + date + "]";
```

## `src/test/java/com/expensetracker/ArchitectureTest.java`

Not in a sub-package — it is about the whole tree.

```java
class ArchitectureTest {

    private static final Path SOURCE_ROOT = Path.of("src/main/java");

    @Test
    void onlyStoreImportsJavaSql() throws IOException {
        assertNoImport("import java.sql", "/store/");
    }

    @Test
    void onlyUiImportsJavaFx() throws IOException {
        assertNoImport("import javafx.", "/ui/");
    }

    private void assertNoImport(String forbidden, String allowedPathFragment)
            throws IOException {
        try (Stream<Path> paths = Files.walk(SOURCE_ROOT)) {
            List<String> offenders = paths
                .filter(p -> p.toString().endsWith(".java"))
                .filter(p -> !p.toString().replace('\\', '/').contains(allowedPathFragment))
                .filter(p -> readSafely(p).contains(forbidden))
                .map(Path::toString)
                .sorted()
                .toList();

            assertTrue(offenders.isEmpty(),
                () -> forbidden + " is only allowed under " + allowedPathFragment
                      + ", but found in:\n  " + String.join("\n  ", offenders));
        }
    }

    private static String readSafely(Path p) {
        try { return Files.readString(p); }
        catch (IOException e) { throw new UncheckedIOException(e); }
    }
}
```

### Two caveats, worth knowing rather than fixing

- **It runs from the working directory.** `Path.of("src/main/java")` resolves against
  wherever the JVM was started, which Maven sets to the project root. Fine here; it
  would need `${project.basedir}` in a multi-module build.
- **It matches text, not meaning.** Someone could write
  `java.sql.Connection c = ...` with a fully-qualified name and no `import` line, and
  slip past. A real project would use ArchUnit, which inspects bytecode. For learning to
  *read* dependency direction, grepping the import block is arguably better — it is
  exactly what your eye does when you open a file.

The `App` and `Launcher` classes at the root of `com/expensetracker/` will import
`javafx.application.Application` from sprint 13 and break the second test. When you get
there, add an explicit allowance for those two filenames — and notice that you are
documenting the one deliberate exception rather than weakening the rule.
